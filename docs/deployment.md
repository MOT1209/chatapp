# Deployment (Render)

The backend (REST + WebSocket) and PostgreSQL are described in [`render.yaml`](../render.yaml).
Only the backend is deployed this way; the Flutter clients are built by
`.github/workflows/release.yml` (see [Releases](./development.md#releases-web-android-windows)).

> Status: the Blueprint is untested against a live Render account. It was validated locally
> (YAML parses; a production-mode build with dev dependencies, `prisma migrate deploy`,
> `/health`, register/login and an authenticated WebSocket all worked against a local
> PostgreSQL). The first real deploy is the actual proof.

## First deploy

1. Render dashboard → **New** → **Blueprint** → select this repository (branch `main`).
2. Render creates the `chatapp-db` database and the `chatapp-api` web service. The two JWT
   secrets are generated by Render; `DATABASE_URL` is wired from the database.
3. `CORS_ORIGIN` is asked for but can stay empty: native apps (Windows, Android) send no
   `Origin`. Set it only if you host the web client (comma-separated origins).
4. Wait for the deploy to go live, then note the service URL, e.g. `https://chatapp-api-xxxx.onrender.com`.

## Verify

```bash
curl https://<host>/health                     # {"status":"ok","service":"chatapp-api"}
curl -X POST https://<host>/api/auth/register -H 'content-type: application/json' \
  -d '{"username":"smoke","email":"smoke@example.com","password":"a-long-test-password","displayName":"Smoke"}'
```

Then open a WebSocket to `wss://<host>/ws` and send `{"type":"auth","payload":{"token":"<accessToken>"}}`; you should receive `ready`.

## Point the clients at it

In GitHub → Settings → Secrets and variables → Actions → **Variables**, set:

| Variable | Value |
| --- | --- |
| `API_URL` | `https://<host>` |
| `WS_URL` | `wss://<host>/ws` |

Then run the **release** workflow again (Actions → release → Run workflow, or push a new tag).
Builds made before this point talk to `localhost` and must not be published.

## What the Blueprint does

- Build: `npm ci --include=dev && npx prisma generate && npm run build`. Dev dependencies are
  required because `typescript` and `prisma` are devDependencies, even though `NODE_ENV=production`.
- Start: `npx prisma migrate deploy && node dist/server.js`. Migrations are applied on every
  start; safe because there is one instance.
- Production refuses to boot with weak or identical JWT secrets (`backend/src/config/env.ts`).

## Troubleshooting

**Build log shows `Running build command 'yarn install; yarn build'` and
`error TS2688: Cannot find type definition file for 'node'`.**
The service was created by hand (New -> Web Service) instead of from the Blueprint, so
`render.yaml` was ignored and Render built the repository *root* with its defaults. Root
`yarn build` also tries to build the Flutter app, which cannot work on Render. Fix, either:

- Delete the service and create it via **New -> Blueprint** (recommended), or
- Edit the service settings: **Root Directory** `backend`; **Build Command**
  `npm ci --include=dev && npx prisma generate && npm run build`; **Start Command**
  `npx prisma migrate deploy && node dist/server.js`; **Health Check Path** `/health`;
  environment `NODE_VERSION=22`, `NODE_ENV=production`, `DATABASE_URL` (the database's
  internal connection string), `JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` (each at least
  32 random characters and different from each other, e.g. `openssl rand -base64 48`).

**Render uses a very new Node (the log said 26.x).** `package.json` only requires `>=20`, so
Render picks the newest. The project is tested on Node 22 (CI); set `NODE_VERSION=22`
(already in `render.yaml`).

## Known limits

- **Single instance only.** The realtime hub is in-memory; more than one instance breaks message
  push, typing and presence. See [architecture](./architecture.md).
- **Plan limits (check Render's current terms, they change).** The Blueprint uses `plan: free`
  for both resources. Free web services typically sleep when idle: the first request is slow and
  every WebSocket connection is dropped. Free databases may be time-limited. Use paid plans for
  anything users depend on.
- **No email provider.** In production `forgot-password` returns 202 and sends nothing, so password
  reset does not work yet.
- HTTPS/WSS is provided by Render. `trust proxy` is set to 1, matching Render's single proxy hop.
- No monitoring, backups policy or log shipping is configured.
